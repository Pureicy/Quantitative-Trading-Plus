# MARKET RADAR SCAN

## 交互流程

点击“一键扫描双低转债”后：

1. 当前工作区上覆盖深色 HUD 扫描层；
2. 雷达动画由客户端播放；
3. AkShare 与 Pandas 扫描在后台线程执行；
4. 后端通过 `ScanProgress` 回调推送真实阶段；
5. UI 每次只更新阶段文字、进度和阶段状态，不重建后台粒子层；
6. 扫描超过 3 秒后显示“后台运行”；
7. 完成后展示 100% 状态，停留 550ms 再进入结果页。

## 阶段与真实进度

| 阶段 | 实际动作 | 完成进度 |
| --- | --- | --- |
| `PREPARE` | 初始化本地数据文件 | 6% |
| `MARKET_MATRIX` | 拉取和交叉校验市场快照 | 48% |
| `REDEEM_SHIELD` | 同步并过滤强赎名单 | 58% |
| `LOCAL_PORTFOLIO` | 读取持仓和自选池 | 66% |
| `DOUBLE_LOW_RANK` | 双低评分、过滤和排序 | 82% |
| `SNAPSHOT_ARCHIVE` | 写入扫描快照 | 92% |
| `REVIEW_SYNTHESIS` | 生成快照复盘 | 96% |
| `PUBLISH` | 返回候选池 | 100% |

进度不会提前越过尚未完成的真实阶段。网络请求等待期间，雷达继续旋转，
状态文案显示当前数据源，进度条只平滑逼近当前阶段目标。

## 客户端雷达

`assets/scan/radar-sweep.webp` 为透明循环动画，包含：

- 三圈同心扫描环；
- 64 个刻度；
- 冰青色旋转扫描扇面；
- 中心定位点和准星；
- 电光紫中心核心。

动画由 Flutter 客户端播放，不经过 Python 帧循环。

## 后台线程

扫描通过 `threading.Thread` 执行，进度事件进入线程安全队列。Flet 主事件循环
每 100ms 读取队列并更新界面，因此鼠标和卡片 hover 不会被网络请求阻塞。

## 完成与异常

- 成功：进度到 100%，状态变为 `SCAN COMPLETE`，然后淡出到结果页。
- 失败：显示 `SCAN INTERRUPTED`、错误摘要和“重新扫描 / 关闭”按钮。
- 收起：超过 3 秒可以切换为右上角小型进度卡，扫描继续后台执行。

## 验收清单

1. 点击扫描后立即出现扫描 HUD，不需要等待网络请求完成。
2. 雷达扇面连续旋转，窗口拖动和卡片 hover 不受影响。
3. 扫描进度依次经过真实阶段，不出现未执行就跳至 100%。
4. 市场快照阶段可显示当前数据源和已加载数据源数量。
5. 强赎过滤阶段完成后显示强赎数量。
6. 双低排名阶段完成后显示候选数量。
7. 扫描超过 3 秒出现“后台运行”。
8. 点击“后台运行”后扫描不中断，主工作区恢复可操作。
9. 后台模式继续显示小型扫描进度。
10. 扫描成功时进度补到 100%，出现 `SCAN COMPLETE`。
11. 完成提示停留后自动关闭，结果表正确刷新。
12. 网络异常时显示 `SCAN INTERRUPTED` 和错误摘要。
13. 失败后可点击“重新扫描”再次执行。
14. 失败后点击“关闭”恢复工作区，不保留忙碌状态。
15. 扫描期间不能重复启动第二个扫描任务。
16. 扫描动画不产生 Python 逐帧刷新，资源由客户端播放。
